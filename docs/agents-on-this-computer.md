# Coding agents on this computer

Togle lists the tasks of the coding agents on your computer (Claude Code, Codex and Hermes) in one place, and lets you answer what they ask. Each task opens as the agent's own screen: the program you know, in a terminal of Togle's own, with its keys and commands as in your terminal. The work does not live in the screen: a Claude Code task is one of its own background sessions, a Codex task is a thread on Codex's shared server, and a Hermes task is a session in Hermes's gateway. So a task goes on when you close its screen or quit Togle. Togle never reads their sign-ins.

## Agents

**Agents** in the sidebar opens the list. A task that waits for you comes first, with the command it wants to run shown in full.

- **Allow once** lets that one command run. **Refuse** tells the agent no.
- **Always allow…** shows when the agent offers to remember the choice, and says how far it reaches: for Claude Code, the rule it suggests and where it keeps it (this task, this project, or everywhere); for Codex, the words the commands start with, wherever they run; for an agent added through ACP, its own option. Togle passes on only that, never a change of the agent's permission mode. It is not offered for a command that looks dangerous, nor in a notice.
- An open task says how it stands and how many files it changed. Its conversation is in the Chat view (below).
- A command that looks dangerous (it deletes for good, pushes over what is on a server, runs hidden text, changes the computer) carries a red mark and the reason. The mark is a hint. The command shown is what runs.
- **New task** opens the task box (below). A Claude Code, Codex or Hermes task follows your own settings, as in your terminal. A task of an agent you added through ACP asks before every command and every change.
- **Stop** ends what the agent is doing. In Chat it is the round button at the right of the reply box: **Send** while there are words or a picture to send, **Stop** (a square) while the agent works or waits and there is nothing to send. In Terminal there is no Stop button, in the header or anywhere: the agent's own screen is shown, and you stop it there, with Esc (Ctrl+C in Hermes), as in any terminal. The round button does what Esc does on the agent's screen (Ctrl+C in Hermes). Your other devices can Stop it too. For a Claude Code task Togle presses Esc on its screen (opening the screen out of sight when it is closed, which takes it from a terminal of your own that has it open, as a reply does; and waiting about two seconds for a screen just opened, which loses a key pressed sooner): the turn and the command it was running end, the session and its conversation go on, and what was queued starts as its next turns, as in Terminal. Togle presses Esc once, and not at all for a task that is not at work: two Esc close together open Claude Code's rewind menu on an idle prompt. Where the screen cannot be opened, the session is ended instead (opening it again brings it back). Codex lets a command that was already running finish, so a stopped Codex task shows a second button, **End the running command**.
- What finished in the last day stays in the list; older tasks fold under **Earlier**.
- A task that runs in a terminal or in an app shows in the list too. For Claude Code, **Take over** ends the program in the terminal and moves the same conversation into the background, with its screen here. Togle asks first. See "Claude Code's own screen" below.
- A task that stops by itself (a turn that ends with an error, or an agent program that stops) waits for you like a question, and its row says why. When the error means the agent is signed out, the row says so with the command that signs it in again (`claude auth login`, `codex login`) and **Copy**: run it in a terminal, then go on. The words that count as signed out are in `isSignedOut` in `src/shared/runner.ts`; Claude Code's and Codex's were seen on this computer. A Hermes task is its own screen, which shows Hermes's errors itself (a model that does not answer, a sign-in that is missing: `hermes model` sets it): Togle does not read them, so its row says Idle.
- With no agent installed, Agents names Claude Code, Codex and Hermes, each with the one line its maker gives to install it and a link to its page. Togle looks for agents the way a terminal would: when one is not found, it adds the PATH saved in the registry (Windows) or the one the login shell sets up (Mac and Linux), so an agent installed while Togle runs shows within a minute. The login shell runs your start-up files, so Togle asks it at most every ten minutes, with no input, and stops it after five seconds; the usual folders (`~/.local/bin`, Homebrew's, `/usr/local/bin`) are checked every time.
- Quitting Togle while a task it runs has not finished asks first. A Claude Code, Codex or Hermes task goes on: the question names the ones that are working or waiting for you, and says so. Togle finds a Claude Code or Codex task again when it starts; a Hermes task is a session in Hermes's list, which opens again from there. A task of an agent added through ACP is stopped, with the commands it started, when you quit.

Hermes asks about a command only when its own settings say to. With its approvals turned off, it never asks, and there is nothing to answer. When it does, it asks on its screen.

## The agent's own commands

Type `/` in the reply box of a task of an agent added through ACP, and the agent's own commands open over the box, each with what it does in the agent's own words. Togle keeps no list of its own: it shows what the agent tells it. (A Claude Code, Codex or Hermes task has no reply box: its screen is the agent's own, and its `/` menu opens there, with all of its commands.)

- Go on typing to narrow the list: the commands whose name starts with the letters come first, and when none does, the ones that hold them anywhere (a plugin's `supabase:…`).
- The arrow keys move, **Enter** or a click sends the command as it is (the agent says what it needs), **Tab** completes its name so you can type what follows it, and **Esc** closes the list.
- `/model` lists the agent's models, and picking one switches the task to it. An added agent that speaks ACP is switched the way ACP has for it, and then asked which model it is on, so the answer is its own. Other words after `/model` go to the agent as they are. A switch the agent refuses ends with which model it was and the reason the agent gave.
- The answer shows as what the agent said. A command that the agent does not know goes to its model as ordinary words.

What each agent tells:

- An agent added that speaks ACP tells the commands it has for a session, and the models it can switch to.
- A task in a terminal of Togle's own, and a Claude Code, Codex or Hermes task, is the agent's real program: its commands work there as they always do.

On a Claude Code screen two commands do more than answer. `/clear` empties the conversation: Claude Code goes on in a new session under the same background session, and the task stays the same one in Togle. Once the task is stopped and Togle has been closed and opened again, the conversation before the clearing and the one after it show as two tasks. `/compact` takes a minute or more, with the task working meanwhile.

## Notices

When a task waits and Togle is not in front, a small notice appears in the corner of the screen with the task, the command in full, **Allow once**, **Refuse** and **Open**. It does not take the keyboard, and it is kept out of screen shares and recordings.

- **Allow once** is held for about a second after a notice appears, so a click meant for the window under it cannot allow a command.
- It is not offered for a command that looks dangerous, or one too long to show in full. Those are allowed in the Togle window, where all of the command is shown. A question from an agent has only **Open**.
- A task that finishes or stops with an error shows a notice for a few seconds.
- The tray icon carries an amber dot, and its menu says how many tasks wait, until none does.

## Task box

**F10** opens a small box over whatever you are doing. Pick the agent and the folder, type the task (or hold the dictation key and say it), and press Enter. The task starts, goes on the to-do list, and the box puts itself away. **Esc** closes it, and so does a click elsewhere; what you typed stays for next time, and so do the agent and folder you picked. The key is a setting like the others (**Settings → Keys**), and F10 can be changed there if another program needs it.

Every way of giving work to an agent opens this same box: **New task** in Agents, **Give to an agent** on a to-do item, and `togle run claude` in a terminal. A call is given from its own page (see Giving a call to agents, below). Opened from a to-do item, it has the item's words and a chip naming the item; the task that starts is given to that item. **×** on the chip makes it a task of its own.

## Settings

**Settings → Agents** lists Claude Code, Codex and Hermes, found or not. The task box key is under **Keys** (Task, F10).

**Add an agent** takes any other agent, by a name and the command that starts it, as its own docs give it, and asks nothing about how it runs. Togle tells from the command, and starts nothing to find out. A command that asks for ACP, the open standard Hermes uses, is talked to directly: its program or an argument has `acp` in it (`gemini --experimental-acp`, `goose acp`, `npx @zed-industries/codex-acp`; a folder's name does not count). Any other command, and one with `{task}` in it, runs in a terminal of Togle's own (below). Togle runs that command on this computer the way a terminal would (an agent installed with npm on Windows starts through cmd.exe). The agent then shows like the others: in the list, in the task box, and as `togle run acp-<name>`. An agent that speaks ACP and says it can list its sessions (`session/list`) has its existing sessions listed too, the ones you have in its own app or terminal, and opens one the way ACP has for it (`session/resume`, or `session/load`); Togle starts the agent's program once to ask, and does not ask again for a minute when that fails. An agent that speaks ACP but does not offer the list (Grok's `grok agent stdio` offers `loadSession` only) lists only the tasks Togle started with it, and so does an agent that runs in a terminal. It asks before a command as its own settings say, and "always allow" is its own option, in its words. **Remove** takes it off again; what it ran is not undone. **Remove** is on Claude Code, Codex and Hermes too: it asks first, then takes the agent off Togle's lists (its tasks, the ones Togle runs too, are no longer shown). The agent stays installed and its tasks go on in it. It is kept in Settings, and listed as *Removed* with **Add back**, which lists the agent again and takes up the tasks it kept going meanwhile.

## An agent without ACP, in a terminal of its own

An agent added with a command that is not for ACP has its tasks run in a terminal of Togle's own (a pseudo-terminal, through [node-pty](https://github.com/microsoft/node-pty)), in the task's folder, and the task's panel is that terminal: you read the agent there and type into it as in any terminal, and F9 types into it as one line. Togle opens on the task when it starts. Its id is `term-<name>` (`togle run term-aider …`).

- Put `{task}` in the command where the task's words go: `cursor-agent {task}`, `aider --message {task}`. They go in as one argument, as written, quotes and all; colors and control characters (a Ctrl+C, say) are taken out.
- Without `{task}`, the words wait above the terminal, and **Type them in** types them, as one line and without Enter: you press Enter once the agent is ready for them.
- On Windows an agent installed with npm or pnpm is a `.cmd` file: Togle reads what it starts (Node and the agent's script) and starts that, without cmd.exe, so `{task}` works as above. Any other `.cmd` or `.bat` starts through cmd.exe, which would read the words as commands: there they wait to be typed in, and the flag that held them (`--message` in `--message {task}`) is left out too. A file that is not a program is refused before anything starts.
- Togle cannot read what such an agent asks. It shows no command before it runs, marks none dangerous, and sends no notice: the agent asks in its terminal, and you answer there.
- The task is working while the program runs, idle when it ends by itself, and stopped by an error, with the exit code (or the signal, on a Mac and Linux), otherwise. Ctrl+C in the terminal stops its turn; **End it** ends the agent and what it started. An ended task does not wait for a reply: it ended with its program. The tasks end with Togle, are not picked up again, and leave nothing behind.

## To-do

**To-do**, the screen Togle opens on, is your list. What waits for you is at the top, with the same buttons as in Agents. Below it is your own list.

The list is a plain text file you can also open in any editor: `to-do.md` in Togle's data folder (`%APPDATA%\togle` on Windows). Each item is a line of a Markdown checklist:

```
- [ ] Review the onboarding copy
- [ ] Fix the login redirect <!-- togle:task=claude:3f2a9c1e -->
- [x] Send the invoice to Marta
```

Lines that are not items are left as they are. An item given to an agent keeps the task in the comment at its end. A change in an editor shows in Togle, and a change in Togle names the item by its line and its words, so it cannot land on another item if the file was edited meanwhile.

**Give to an agent** opens the task box with the item's words filled in. The item then shows what the task is doing, and that it is idle when it has finished. You tick the item yourself once you have looked. A task started any other way (the task box on its own, **New task**, the `togle` command) gets an item of its own, so every task you give an agent is on the list.

## From a terminal

The `togle` command starts a task in the running Togle from any terminal, and lists the tasks:

```
togle run claude                               # opens the task box with Claude Code and this folder
togle run codex --folder ./api "Add a status column to the orders table"
togle run "Fix the failing login test"         # Claude Code, in the current folder
echo "Review the onboarding copy" | togle run  # piped text is the task
togle tasks
```

The first word names the agent: `claude`, `codex`, `hermes`, or the id of one added in Settings (`acp-…`). Without one it is Claude Code; a task that starts with one of those words goes after `--`. With no task, Togle's task box opens with that agent and folder, for you to type or say it. A script that pipes in nothing is told to say what the task is, and no box opens.

The task shows in Agents like any other and goes on the to-do list. It follows the agent's own settings, as in your terminal; only a task of an agent you added through ACP asks before every command and every change. The command talks to Togle over a local channel (a named pipe on Windows, a socket file elsewhere), where both ends prove they hold a secret kept in Togle's data folder, so it needs Togle running, and it says so when it is not. It exits with 0 when it worked, 1 when Togle could not do it, and 2 when the command was not understood.

The command is the program `out/main/cli.js`, started by Electron as plain Node (`ELECTRON_RUN_AS_NODE=1`). From a copy of the source, run `npm run build`, then `node bin/togle.cjs tasks`, or `npm link` to get `togle` on your path. An installed Togle has the command beside the app in `resources/bin` (`togle.cmd` on Windows, `togle` on Mac and Linux); add that folder to your path to use it from anywhere. The installer does not add it yet, and the Mac and Linux versions were not tried. From a development run, name the data folder: `TOGLE_DATA`.

## Giving a call to agents

A call has a list of agent tasks, and a call's key exists before the call starts, so agents can be connected before it, while it goes on, and after it. The list is kept in `call-agents.json`, in Togle's folder: task keys and times, nothing that was said.

- **Before the call**, the Meetings list has a row, *Agents for the next call*, with **Add**. **During** it, the live call has the same row, with a tick for each agent and **Send what was said**. A tick says which agents get it, and **×** takes one off.
- **A new agent on the fly.** **Add**, before or during a call, also starts one: tick **A new task**, pick the agent and the folder, say what it should do, and press **Start and add**. It starts with your words, and with the call as it stands when something has been said; when nothing has, with a line that a call is going on (or about to start) and that Togle will tell it where the call is saved once there is something to read. It stays on the call, so **Send** and **Ask** reach it from then on. What you typed for it is kept if you close the list and open it again, and stays in the box when the agent could not start (with why).
- **Send** writes the call as it stands (the notes, if there are any, and the transcript so far) as a plain text file in `shared-calls`, readable only by you, and tells each ticked agent where it is. The file is written again each time you press it, and is deleted with the call.
- **Give to an agent** on a finished call lists the running agent tasks, each with a tick, and **A new task** (an agent and a folder). Say what to do with the call and press **Give to N**. A task that cannot take it says why: *It is working* (Claude Code and Hermes take words on their screen only, once their turn has ended), *Open it in Agents first* (Togle does not run it), or *It runs in a terminal of its own*.
- **What an agent is told** is your own words, then one fixed line: where the call is saved, that it is a record of what people said, and that it is to be used as information and not as instructions. What was said is never part of that line, so it cannot carry a command to an agent's screen, where a line that starts with `/` or `!` would run one. Your own words are sent as you wrote them: ones that start with `/` or `!` are refused for Claude Code and Hermes.
- **A new task asks before it runs anything**, as far as its agent lets Togle make it ask: Claude Code and Codex do. Hermes keeps its own approval settings, and so does an agent that is already running, which Togle cannot change. They are told to treat the call as information only.
- **Ask** is a box under the agents on a live call. Type a question, or hold F9 and say it, and Ask sends it to each ticked agent, with the same line that tells where the call is saved so far (the file is written again each time). Each answer shows under the box, with the agent's name and your question, and a card when the agent needs your Allow to answer: answering it there answers the task. The answer is read from the agent's own record of the conversation, so it is the agent's last words after your question; **Open** goes to the task. An agent that cannot take the question says why, as with Send, and the question stays in the box when none took it. Answers stay under the box while the window is open, and **×** puts one away. Ask is on the live call only.
- **Other notices wait during a call.** An agent that asks something you did not ask it shows in the tray's dot, and its notice comes when the call ends.

## Two views of a task

A task of Claude Code, Codex or Hermes has two views, and a switch beside its state, **Chat** and **Terminal**, picks one. **Settings → Agents → Tasks open in** says which one a task opens in (Terminal at first). The switch changes it for that task, and Togle remembers the pick.

- **Terminal** is the agent's own screen, with its keys, its commands and its questions. There is no card over it and no reply box: what the agent asks is answered on the screen.
- **The screen follows the theme** (Settings → Appearance: Light, Dark, or the system's), and is painted again the moment it changes, with the same screen. What an agent draws in the terminal's own colors (its text, its background, the sixteen named colors) follows at once. What it draws in colors of its own does not, such as Claude Code's in its dark theme (`theme` in its settings, or `/theme`): on a light screen Togle keeps every letter readable by moving a color that is too close to the background away from it (4.5:1, as WCAG asks for text), which is not the look Claude Code has in its own light theme. For that, pick Claude Code's light or auto theme in Claude Code itself; Togle does not change an agent's settings.
- **Chat and Terminal both stay in the window once you have shown them.** Switching from one to the other does not start either over: Chat is where you read it to, with what you opened still open, what you selected and what you typed; Terminal is scrolled where you left it. A screen that is closed is let go of, and the one that opens next starts afresh.
- **`/resume` and `/exit` are kept off the screen.** Typed on an agent's screen, `/resume` would put another conversation under the task, and `/exit` would take the screen out of it: Claude Code's goes to its list of every session on the computer (where Ctrl+X removes them), Codex's closes, and Hermes's closes and, with `--delete`, removes the session's history. So when Enter is pressed with one of them on the line (`/resume`, `/continue`, `/exit`, `/quit`, and Hermes's `/sessions`), Togle does not send it. It empties the line, and a note over the screen says to press **Hand back** to leave the screen, or to pick another conversation in the list and press **Continue here**. The line is read from the screen as well as from the keys, so the start of a name that the agent's command list is about to run on Enter is caught too (`/ex`, `/qu`, or an arrow key down the list; Claude Code lists a command with its other names, `/exit (quit)`, and the highlighted row is read as that command), and only the whole name: `/exit-codes` goes through, like every other command. The `←` key is kept off too, for the same reason: at an empty prompt it takes Claude Code's screen (after "Press ← again to go back to agents") and Codex's (at once) to that same list of every session, as `claude attach --help` says. Togle does not send it there, and the note says so. An empty prompt is told by its placeholder, which the programs draw dim; with text in the prompt `←` moves the cursor as usual. Hermes has no such key, so its `←` goes through. What Togle cannot see: a screen that has not drawn the line yet is judged by the keys alone. A `/resume` that gets through is handled as a cleared conversation: the task keeps its id and follows the new session. Only the agents Togle has tried are guarded; an agent you add that runs in a terminal of Togle's own is not.
- **Chat** shows the conversation as a chat, and keeps what the agent did out of the way: the Terminal view has all of it as it was. What you said is a card of its own, marked **You**, and what the agent answered is plain words under it, formatted. A picture you put in (pasted, a screenshot) shows small in your card with its own proportions (a wide strip is shown whole, as wide as the card lets it be and at most 112 pixels high, and never made bigger than it is), and opens whole over the window when you press it (Claude Code's; a picture a tool read is not shown). The last thing you said, what the agent works on, stays at the top of the conversation while its turn is in view, so it is always there; the ones before scroll away with their turns. A long one shows its first three lines (two in a low window) and **Show all**. A turn that is over shows one quiet line for the work, **Worked for 4m 8s** and in brief what it changed and ran ("Changed 4 files, ran 5 commands, 1 failed"), then the answer with when it came, and **Copy** when the pointer is on it. Press the line to see the details: what the agent said along the way, each stretch of steps as its own line, and each step named by what it touched ("Read plans.ts", "Ran npm test", "Searched for yearly", "Opened example.com/pricing", "Asked a helper: …", "Thought for 8s"), with how long it took. A step that failed is red; one that went well has no mark of its own. Press a command to see all of it and what it printed (its end, with keys and passwords blanked, and **Copy**), a file it changed to see how it changed (the lines taken out in red and the lines put in in green, as the agent's own record has them; a file it wrote whole shows all of its lines as put in; a long change shows its start; keys and passwords blanked, and **Copy**), and a thought to read its words where the agent kept them (Hermes keeps them; Claude Code keeps them now and then, and Codex rarely). The turn going on shows what the agent says, each stretch of steps as one line that says what it does now, with the step it runs under it and how long that has run; the steps before the latest eight parts are behind **Earlier in this turn**. When no step runs, a last line says it works, with a clock for the turn. What is asked of you floats over the foot of the conversation, as the agent's own screen has its prompt in it: the conversation scrolls under it and keeps room for it at its end. A card for what the agent asks (**Allow once** and **Refuse** for a command or a change, the choices for a question); the agent's own checklist for the turn, when it keeps one (Claude Code's tasks, Hermes's to-do list), with every item it has in its own order, done, being done and left, in a card of about twelve rows (a longer list scrolls in it, and the item being done stays in view; past a hundred and fifty items the oldest finished ones are let go of); what you queued; and the reply box. The box grows with what you type: **Enter** sends, **Shift+Enter** starts a new line. A screenshot pasted into the box (**Ctrl+V**) is a chip over the words with the picture, its name and where Togle keeps it, and a small button at the chip's top right that takes it out; pressing the chip opens the picture whole over the window with **−**, **+** and the percentage (the keys **-**, **+** and **0**, and **Ctrl** with the wheel, do the same). It goes with the words as the path of its file (Togle keeps it a week), which Claude Code and Codex take as a picture to attach and any other agent can open; once sent it is drawn small in your card, in the queue and in the list of questions, and not as a path. Chat shows the last twelve turns, and **Show earlier** brings the rest in above what you were reading. When you have scrolled up, **Latest** goes back to the newest words.
- **A rail of your questions** sits at the right edge of a Chat conversation from the third question on: a small tick for each, the one you are reading lit. Point at a tick (or move to it with the arrow keys) to see the question and when you asked it, and press it to go to that question. The conversation stays there while the task goes on: new words do not take you back to the end until you press **Latest**. When only the last turns are read in, the first tick, a dotted one, brings the earlier ones in, as **Show earlier** does. The rail takes 22px of the conversation's width while it shows.
- **Quote and reply.** Select part of one message in Chat, what the agent said or what you said, and a **Quote** button shows over it once you let go of the mouse. Press it, and the part sits over the reply box, with a cross to take it away (Esc does too). What you send goes with it as one line, `Replying to “the part”: your reply`, so the agent can tell what you answer, and Chat draws the part as a quote over your words, in your card and in what waits to go in. A part is cut at 500 characters. It goes with one reply only. A command (a line that starts with `/` or `!`) goes alone and the quote waits; the answer to a question the agent asks goes as the agent asks for it, and no Quote shows then. A selection over two messages has no button. Sending a reply takes the conversation to its end, wherever you were reading.
- **Chat reads the conversation from the agent's own record of it**, not only from what Togle saw. So it shows what was said before Togle opened the task, and the conversation of a task that runs in your own terminal, read-only. Claude Code keeps it in the session's file under `~/.claude/projects`, and Togle reads only what the file gained since the last look. Words typed in the terminal while Claude Code is working are in the file as a queue line and, once the turn takes them in, an attachment, never as a message; Chat shows them as soon as they are queued, and takes them off again if they are taken back or came from a finished task or another session. Codex keeps it on its server, and Togle asks for the newest turns with every step and, for **Show earlier**, the older ones with what was asked and answered. An agent you added that keeps none Togle can read shows what happened while Togle watched.
- **A task is working only while its turn runs.** A Claude Code task whose turn ended while a command it started still runs in the background is **Idle**, and says so in its row ("idle · 1 shell running") and in the line under its name ("1 shell running": only how many, right after the agent's name; the commands are on the pointer). On that line the files changed are always the last thing before the switch of views, whether a shell runs or not. Claude Code's list calls such a session busy, so Togle reads the program's own record in Claude Code's folder (`sessions/<pid>.json`, whose status is `shell` then, and the job's `state.json`, which lists the shells). Such a task gets its turn-ended notice, words typed in Chat go in at once instead of waiting, and it is not put to rest while a command runs (that would end the command too). A session that waits on a **monitor** (Claude Code's Monitor tool, say "watch the CI runs") is a different case: its turn is over too, but it goes on by itself when the monitor says something, so it is **Working** and says "waiting on 1 monitor" in its row and in the line under its name, before any shells (the description is on the pointer). The program's record calls it `shell` as well (a monitor is a command), so Togle tells the two apart by the job's `state.json`, whose `fan` lists each item as `shell` or `monitor`. A monitor that has finished waits on nothing, and the task is Idle again.
- **The line under a task's name says which model it works with and how hard it thinks**, right after the agent's name: "Opus 5.5 · max", "GPT 6.2 Sol · ultra". The pointer shows the model's full id and the effort in words ("Model: Opus 5.5 (claude-opus-5-5). Effort: max."). Togle asks the agent's own record: Claude Code's last answer in the session's file (its `model` and `effort`, never a helper agent's), Codex's thread (`model`, `reasoningEffort`), Hermes's session export (`model`, and the reasoning effort in `model_config`, "off" when reasoning is off). It is read when you open the task, when the task changes, and every five seconds while it works or waits, so a model you change on the agent's own screen shows within a moment. An agent that tells neither (an ACP agent, an agent in a terminal of your own, a session with no answer yet) shows no words, and a reading that tells nothing leaves what was shown.
- **No notice comes while Togle's own window is in front**, in either view. The list, the To-do count and the tray's dot say what waits, and a screen on show asks on itself. A notice comes once the window is not in front (behind another app, minimized or in the tray). During a call, notices wait, as always.
- **A reply typed in Chat goes through the agent's own screen**, since Claude Code and Hermes take words nowhere else. Togle opens the screen out of sight when it is closed, waits until it is drawn, types the line and presses Enter. That takes the screen from a terminal of your own that has it open, as opening the task here does. **Claude Code takes a reply while it works.** It is typed in at once, into the agent's own queue, exactly as if you had typed it on its screen in Terminal, and the agent takes it in as it goes (at its next step, often within a minute) and not only when the turn ends. That queue is one: what you send here and what you type on its screen are listed together in the **Queued** card over the reply box (Terminal shows the same queue under its prompt), each message in the order it was typed, until the agent takes it in and it becomes a line of the conversation, with the time you typed it. To change or remove what is queued, press **Take back** on that card: it presses the Up arrow on the agent's screen, as you would in Terminal, which gives the whole queue back to the prompt, then empties the prompt again, and the words come back in the reply box, in the order they were queued (behind what was already typed there). Change them, delete some, and send them again; they go in as one message, as the screen would send them. It is all of the queue or none: Claude Code's Up arrow gives back everything, so there is no taking back one message of it. A message the turn took in before the key came is already in the conversation, and is not in the box. Togle believes the arrow only when Claude Code's record shows the queue came back; if it does not (the turn had taken it in by then), Togle presses Down, which puts back what the arrow did (an earlier prompt, or the cursor), says nothing was changed, and leaves the box alone. The prompt on its screen is emptied after a take back: a draft you were typing there goes too. Nothing is pressed that could stop the turn (not Esc, not Ctrl+C), and nothing at all while a question or a permission waits on the screen (the arrow would move its choice; the button is off then). Hermes and Codex have no queue of their own, so the card has no such button there. **Stop** is Esc on the screen: the turn ends and the agent starts what was queued as its next turns, as it does when you press Esc in Terminal. **Hermes takes a reply while it works** too, and also at once: its screen does not queue a line typed meanwhile and does not end the turn, it puts the line in the turn at the next tool as a message from you (measured on Hermes 0.22.5: the command went on, and the answer took the words in), and Chat shows it as one of your messages where Hermes put it. (With its screen closed, Togle opens the screen out of sight and gives it about six seconds to load the session and say by its title whether it works, then types the words; a task whose screen is closed is shown as idle, since Togle hears nothing of it then.) Where a reply could answer a question on the screen by accident (a question or a permission that waits on any agent's screen), the box takes words all the while, and what you send then waits in the same card, a row for each message in the order it will go in, and goes in by itself, all of it as one message, once the agent works again. A row that Togle holds has a cross to take that message back, and **Edit**, which puts it back in the box (while the box is empty). **Interrupt and send** on the card stops what the agent is doing, as **Stop** does, and sends the whole queue now. After **Stop**, or when it could not go in, the queue waits for you instead (**Send now**, with why it did not go in). **Hand back** does not send it: its words come back in the line that says how to open the task in your terminal. It is held while Togle runs: quitting Togle drops it. A reply of several lines is typed there as one line, its line breaks made spaces: on a screen, a line break would press Enter. A reply that starts with `/` or `!` is refused: such a command asks things on a screen nobody looks at, so type it in Terminal. Hermes loads a session slowly when its screen opens, and may not take Enter at once: Togle waits for its screen to be quiet, watches for its window title to say a turn began, presses Enter again (twice at most) when it did not, and says in words when it still did not. Its words are then on its screen, for you to send from Terminal. Codex takes a reply on its server with no screen, and also while it works (the words steer the turn).
- **A message you send is on screen the moment you press Enter**, at the end of the conversation, marked **You** and with ticks that say how far it got, as a chat app draws them: a clock while Togle sends it, one tick when the agent was told, two grey ticks when the agent has it in its own queue (the **Queued** card shows the same two ticks), and two ticks in the accent once the agent took it into the conversation (every message of yours that the agent's record holds has them). If it could not be sent, the card gets a red mark, says why, and has **Try again** and **Remove**. A message Togle holds because the agent cannot take it yet is in the **Queued** card with a clock, and not in the conversation. A command of the agent's own (`/…` or `!…`) is not a message and has no card. The card is the record's own once the agent's record has the message (same words, newer than the press), so there is never a second one.
- **Interrupt** is beside Send while the agent works and words are typed (and **Ctrl+Enter** does the same). Enter queues; Interrupt says it now: it stops what the agent is doing, as **Stop** does, and sends those words as soon as the agent has shown that it stopped. What was queued before is not sent with them: it goes in when the turn they start has ended (a Claude Code task starts what it had queued as soon as it is stopped, so the new words come after it, as when you press Esc and type in Terminal). If the agent has not stopped within a few seconds, the words stay in the box and Togle says so. A command of the agent's own (it starts with `/` or `!`) is refused on a screen before anything is stopped. Codex takes words while it works, so Enter steers it at once, and Interrupt there stops its turn and then sends. With a question the agent asks waiting, there is no Interrupt: the answer goes as the agent asks for it. A Claude Code task is stopped with Esc on its screen, which takes a moment longer when the screen has to be opened first.
- **Each place is as you left it.** Togle draws one place at a time (To-do, Agents, Meetings, Settings), and what you were doing in a place is there again when you come back to it while Togle stays open. Each place is also scrolled to where you left it. In Agents: the task that was open, what you typed for each task and the part you quoted (each task has its own box, and a reply you sent is not typed again), how far you had read each conversation, what you had opened in it (a line of work, a command, a file's change, a long message shown whole, the checklist, earlier turns), where a plain terminal screen was scrolled to, and where the list was scrolled. Another task is the same: each keeps its own. A task asked for from outside (a notice, the to-do list) is shown once, not again each time Agents is drawn. In Meetings: the call that was open and its tab, how many lines of its transcript you had asked for, and the words you searched. In Settings: the rows you had opened (Names and terms, Remembered voices). A menu or a list of choices that was open is shut, as it is on any page. On a live call: which agents are ticked and the question you were typing. In To-do: the new item you were typing. Closing Togle forgets all of it, except the choices that were always kept (which view a task opens in, the groups and what is folded).
- **Hand back** works in both views.

## Claude Code's own screen

A Claude Code task opens in Togle as **Claude Code's own screen**: the program you know, in a terminal of Togle's own, with its keys and its commands exactly as in your terminal (`/model`, `/compact`, `/resume`, shift+tab, pasting an image, all of it). It is one of Claude Code's own background sessions (`claude --bg`), and the screen is `claude attach` in that terminal. What Togle adds is around the screen:

- The task is in the list, **Working** while it answers and **Idle** when it has. A notice says when it is done, with what Claude Code said last.
- When Claude Code asks something, **Chat** shows it: **Allow once** and **Refuse** for a command or a change, the choices for a question. In **Terminal** the screen shows its own question; with Togle's window behind another app or in the tray, a notice says it too. Either one is enough: answer on the card, in the notice or on the screen, and the others go within a couple of seconds (Togle asks Claude Code whether it still waits).
- A plan Claude Code proposes (plan mode) is a card with the plan whole, and two buttons: **Approve the plan**, after which it goes on in the mode that asks before each edit (as "Yes, manually approve edits" does on its screen), and **Keep planning**, which sends it back and Claude Code asks what to change. For the other choice (auto mode) or words of your own, use the screen.
- Nothing is forced on it. It starts with your own permission mode and your own rules, so Togle sees only what Claude Code asks. If yours never asks (it starts in `bypassPermissions`, for example), no card shows for a command, only for what Claude Code asks you in words.
- **It goes on without Togle.** Closing its screen does not stop it, and neither does quitting Togle: the next time Togle starts, it finds the task again and hears it ask. Quitting names the tasks that are working or waiting for you, and says they go on. **Stop** is Esc on its screen: the turn and the command it was running end, and the session goes on with the same conversation.
- **A task that has done nothing for a day is put to rest.** Each session Claude Code runs in the background keeps a program and its memory until it is stopped, so Togle ends the program of a task it runs that has been idle for a day: nothing asked, nothing answered, no screen of Togle's open on it. It stays in the list as **Idle**, with its conversation, and opening it (or a reply in Chat) brings the same session back. Quiet is counted from the latest of what Togle saw the task do, when it started, and when its session file was last written, so a restart of Togle does not begin the day again. A task that works or waits for you is never put to rest, and neither is one you have open in a terminal of your own (`claude attach`): ending that would end your screen. Togle must be running for it to happen.
- **One screen at a time.** Open the task in your own terminal (`claude attach <id>`) and the screen in Togle closes, saying so; open it in Togle and the other closes. A closed screen opens again with **Open the screen**.
- **Hand back** closes the screen here and gives you the line to open it in your own terminal: `claude attach <id>`, to run in the folder the task worked in. The task goes on and stays in the list.
- Your other devices list the task and show its card. They can **Refuse** a command and **Stop** the task, and never type into the screen: a key could answer "1. Yes". **Allow** from a device waits for proof that it is you, which is not built yet, so a command is allowed at its own computer.
- A task started in Togle (the task box, **Give to an agent** on a to-do item, `togle run claude`) follows your own settings, as in your terminal. It does not ask before every command. A task started with a call (see Giving a call to agents) does ask, and so will a start from another device, when that exists.

A Claude Code you started yourself in a terminal shows in Agents with its state, and its row offers **Take over**. It asks first. It ends the program in your terminal, and moves the same conversation into the background, with its screen here: the same session, with its history. It starts the way your program was: the `--model`, `--effort` and `--permission-mode` flags it ran with are carried over, and `--dangerously-skip-permissions` too. Its other flags are not. A Claude Code that has had no message yet has no conversation to move: Take over says so and leaves it running. If the conversation cannot go on in the background, Take over says why and gives the `claude --resume` line to go on in your terminal.

A conversation goes on in one program at a time. Two programs on one session each know only their own half, and the saved conversation splits in two. So Take over ends your terminal's program first, and Togle never goes on with a copy: when Claude Code says it started one, Togle ends the copy and says so.

Some limits, as Claude Code 2.1.323 has them on Windows:

- A folder Claude Code has never been opened in is refused by `claude --bg` until you have run `claude` there once and said yes to the question about trusting it. Togle says so, and nothing is started.
- Togle hears a task by an address on this computer that Claude Code was given when the session started, and a running session keeps it. The address, a secret, and each task's settings file are kept in Togle's data folder (`claude/`), so the same address is served again when Togle starts. If another program has taken that port meanwhile, a task still running from before cannot be heard: its row says what it waits for, and it is answered on its screen. One that is stopped and opened again gets the new address. Taking a task out of Claude Code (`claude rm`) removes it from Togle too; its settings file goes with it.
- While Togle is closed, nothing is shown for a question: Claude Code asks on its own screen, and prints no error for the address that is not there. A request that came then is not posted again when Togle starts: the task's row says it waits on its screen, the tray counts it and a notice says so, and it is answered on its screen. Togle has no card for it.
- A background session is a program that stays until it is stopped, even when its turn is over. Stop the ones you are done with, or leave them: opening a task whose session ended brings it back.
- A task whose words are longer than 20,000 characters is refused: they go in the command that starts it.
- Take over is for Claude Code only. A Codex or Hermes session that runs in your own terminal is opened from the list instead (see below).

## Codex's own screen

A Codex task opens in Togle as **Codex's own screen**: `codex resume <thread>` in a terminal of Togle's own, with its keys and commands as in your terminal. The task is a thread on **Codex's shared server**. Codex keeps one server per computer (its "daemon") that every `codex` joins, and a thread goes on in it whether or not a screen is open. Togle is a second client of that server beside the screen, which is how it hears what the thread does and what it asks. What Togle adds is around the screen:

- The task is in the list, **Working** while it answers and **Idle** when it has. A notice says when it is done.
- When Codex asks to run a command or change files, **Chat** shows it: **Allow once** and **Refuse**, and **Always allow** with the words the commands start with. The screen asks at the same time, and, with Togle's window not in front, a notice says it. Either is enough: answer on the card, in the notice or on the screen, and the other is told it was answered, so the card goes at once.
- Nothing is forced on it. It starts with your own settings. Yours may never ask, and then no card shows.
- **It goes on without Togle.** Closing its screen does not stop it, and neither does quitting Togle: its commands keep running and the turn goes on to its answer, with nobody connected. A question that is open when Togle quits stays open on the server, and the next Togle, or the screen, is asked again. When Togle starts, it finds the tasks it ran that are working or waiting.
- **Stop** ends the turn, as Esc does on the screen. A command that was already running goes on, and a stopped task shows **End the running command** for it.
- **Hand back** closes the screen here and gives you the line to open it in your own terminal: `codex resume <thread>`. A thread that runs in a terminal of your own is in the list too; opening it joins it, and both screens show it.
- Your other devices list the task. They can **Refuse** a command and **Stop** the task, and never type into the screen.

The shared server is Codex's own, and Togle only joins it. It starts it when you start a task, as `codex` does when you run it, and does not start it to list your tasks (they are read from a server of Codex's own, apart from it, while the shared one is not running). The server keeps itself up to date: it may fetch a new release, which is large (about half a gigabyte on this computer), and restart. Togle looks for it again when it does, and a task that was running then is taken up again if it still works. Togle reaches it through `codex app-server proxy`, which Codex offers for this and calls experimental.

Some limits, as Codex 0.169 (the server) with 0.166 (its screen) has them on Windows:

- `/new` on the screen starts another thread in the same program. The task in Togle stays with the first.
- A thread has to have had its first message before it can be joined: a task is started with its words.
- **End the running command** finds the command by its text among what Codex's server runs, so it also ends an identical command that another thread of the server is running.
- Mac and Linux were not tried.

## Hermes's own screen

A Hermes task opens in Togle as **Hermes's own screen**: `hermes --tui` in a terminal of Togle's own, with its keys and commands as in your terminal. Hermes follows your own settings: Togle gives the screen no flag. The conversation is not in the screen. It is a session in the **Hermes gateway**, the background process that serves its messaging platforms (or one a screen starts, which ends itself after ten idle minutes), so it goes on when the screen closes. What Togle adds is around the screen:

- The task is in the list, **Working**, **Waiting** and **Idle**, for as long as its screen is open. Togle reads the screen's window title, which Hermes sets to ⏳ while it works, ⚠ while it waits on an approval, a password or a question, and ✓ when it is idle. A notice says when a turn is done, and a task that waits says it waits on its screen.
- What Hermes asks is answered on its screen. Togle has no card for it: Hermes tells nothing else while a screen holds its session, so Chat says the task waits on its screen and offers **Open the terminal**. With its approvals turned off, Hermes never asks.
- **Stop** is Ctrl+C on the screen: Hermes ends the turn and the command it was running. If the screen is closed, Togle opens it first.
- **It goes on without the screen.** A turn goes on when the screen is closed or Togle is quit, and writes its answer: Hermes's gateway ends a turn only when it has had no news for ten minutes. A session with no turn is let go of by the gateway after twenty seconds, and opens again from Hermes's store. While the screen is closed Togle does not know what the session does: the task rests in the list, and **Open the screen** brings the session back with its history.
- **One screen at a time.** Hermes refuses to open a session that another window holds, and says so on the screen; Togle shows the words.
- A new session is named as the task's words, so that Hermes's own list reads as Togle's does (Hermes keeps one session to a name: a name it already has gets a number, `#2`, as Hermes does itself). A session whose first turn failed, because its model did not answer, is in Hermes's list with no folder, and is found all the same. The sessions in the list are Hermes's own, from its terminal, its terminal screen and its Desktop app, so the sessions you have in the app are tasks here too (not its messaging platforms or scheduled jobs; a session that never got a message is left out, as the app leaves it out). Hermes's list says only the folder's name, so Togle knows the folder only of a task it started.
- Your other devices list the task and can **Stop** it. There is no card for them to refuse.

Some limits, as Hermes 0.22.5 has them on Windows:

- Togle hears the title only while the screen is open. After a restart of Togle, a Hermes task is a row in the list, not a task Togle hears; a to-do line that names the task still finds that row.
- Hermes's own list does not say which sessions are running.
- Closing the screen of a Hermes task while its turn works makes the task read Idle in Togle, and a notice that it finished may show, though the turn goes on in Hermes.
- When no Hermes gateway runs, the screen starts one; whether closing the screen ends that gateway, and the turn with it, was not tried.
- Hermes prints a title cut at 26 characters, so a session taken from its list shows a short title until its screen is opened.
- Mac and Linux were not tried.

An earlier development build of Togle could add an entry to Claude Code's settings that started Togle as `--togle-hook`. That entry now does nothing; take it out of `~/.claude/settings.json` if it is there.
